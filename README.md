# MySQL Query Visualizer

MySQL の **SELECT / UPDATE / DELETE** をブラウザ内で解析し、JOIN・条件・クエリの作用を視覚的に表示する Web UI です。  
SQL の送信や外部 API 通信は行わず、**完全オフライン**で動作します。

## 機能

### SQL 入力

- リアルタイム解析（入力後 400ms）。Ctrl+Enter（Mac は Cmd+Enter）で待たずに解析
- シンタックスハイライトと行番号
- エディタの下のステータスバーに、解析の状態（未入力・解析中・解析済み・構文エラー）とカーソルの行・列を表示
- Tab で字下げ、Shift+Tab で字下げを戻す（Esc を押してから Tab で、次の項目へフォーカスを移す）
- 構文エラーのときは、行と列を表示し、該当箇所に波線を引く。「該当箇所へ移動」でカーソルをそこへ移す。パーサーが期待していた字句の一覧は、右側の「パーサーの詳細」を開くと読める
- 入力した SQL・モード・表示オプションはブラウザ（localStorage）に保存し、リロードしても残る
- サンプル読み込み（SELECT / UPDATE / DELETE / UNION）
  - SELECT: 多段 JOIN・派生テーブル・相関 EXISTS / IN / NOT IN
  - UNION: ブランチごとに JOIN・集約・派生テーブル・サブクエリ
  - 入力していた SQL をサンプルで置き換えたときは、エディタの下の「元に戻す」か Ctrl+Z で前の SQL に戻せる

### モード

| モード | 内容 |
|------|------|
| **単一解析** | 1 本の SQL を解析し、構造・作用・JOIN 図を表示（従来どおり） |
| **SQL前後比較** | 2 本の SQL（変更前 / 変更後）を構文比較し、実行結果に影響しそうな差分をカテゴリ別に表示 |

### タブ（単一解析）

| タブ | 内容 |
|------|------|
| **SQL構造** | 句ごとの SQL 構造（表示対象・結合条件・WHERE・集約・後処理）。クリックで左の SQL と連動（デフォルト） |
| **作用説明** | SQL が苦手な方向けの自然言語説明。JOIN を文章で説明し、要約・WHERE・集約を日本語で表示 |
| **JOIN 図** | テーブル間の結合をインタラクティブなグラフで表示。UNION 時はブランチごとの JOIN 図 |
| **サブクエリ** | IN / EXISTS / 派生テーブルなどネストした SELECT を個別に解析（該当時のみ表示） |

タブとモードの切り替えは、キーボードでは選んでいるタブにフォーカスを置き、← → / Home / End で切り替えられます。

### SQL前後比較

性能改善などで JOIN などを書き換えたとき、**結果が変わっていないか**を構文面から確認するためのモードです。  
主軸は **構文差分の列挙**（実行前の構文レビュー）で、限定した範囲でのみ意味等価を証明します。

- 実 DB への実行や結果行の貼り付けは行いません（完全オフライン・解析のみ）
- 出力列・テーブル・JOIN・WHERE / HAVING・GROUP BY・LIMIT・UNION / CTE などをカテゴリ別に比較
- サマリーは **結果セット**（行の集合）と **並び順**（ORDER BY）を分けて表示します
- LIMIT / OFFSET があるとき、ORDER BY の違いは結果セットにも影響し得ると判定します
- エイリアスの違いは実テーブル名に解決してから比較します（ただし自己結合の別名は解決しません。`u1` と `u2` を同じ名前に潰すと、どちらのインスタンスを出力・絞り込みしているかの違いが消えてしまうためです）
  - この結果、**自己結合で別名を付け替えただけのクエリは「異なる」と判定されます**（合接クエリ範囲なら下記の等価証明で「同じ」になります）。安全側に倒した仕様です
  - 自己結合で片方に別名がない場合（`FROM users LEFT JOIN users u2`）、`users.` がどちらの参照か判別できないため、その識別子は実質 INNER 判定の根拠にしません
- 文字列リテラルは大文字小文字・空白を含めてそのまま比較します（`'A'` と `'a'` は別の値として扱います）
- 式の中のサブクエリ（SELECT 列・関数の引数・SET の右辺など）、派生テーブルや CTE の中の UNION も中身まで比較します
- カテゴリに差分が無いときは、元の SQL の字句（キーワード・列名・リテラル・演算子）の過不足も確かめます。カテゴリが扱わない記述（`PARTITION (p0)`、UNION 全体の LIMIT、WINDOW 句など）が違っていれば **その他の記述** カテゴリに差分として表示し、「同じ」とは判定しません。別名、JOIN や AND の並び順、JOIN 種別の書き方、インデックスヒント、コメントの違いは数えません
- `SELECT *` は FROM 句のテーブル順と USING / NATURAL の有無で出力列が変わるため、これらが違えば出力列の差分にします
- JOIN は、FROM 句を左から結合した木として比べます。次の書き換えは、結果が変わらないので同じとみなします
  - 内部結合の並べ替えと、ON 条件を別の内部結合の ON へ移すこと
  - RIGHT JOIN と、左右を入れ替えた LEFT JOIN
  - 外部結合を、NULL で埋まる側を読まない内部結合の前後へ移すこと
  - 互いを読まない外部結合どうしの並べ替え

  外部結合で行を残す側は、直前のテーブルではなく、それより左の結合全体です。行を残す側が変わる書き換えは「異なる」と判定します
- よくあるリファクタ（INNER の WHERE↔ON など）で証明まで届かないものは **要確認ヒント**（黄）として補助表示します。結果セットの判定は「異なる」のままです
- 緑の「同じ（証明済み）」は、下記の等価証明ができたときだけ表示します。構文のカテゴリに差分が無いだけのときは、色を付けずに「構文の違いなし」と表示します。構文の比較では、関数の細かな仕様や型の変換による違いを見落とすことがあるためです
  - 並び順も、ORDER BY が一致したときは「同じ」ではなく「違いなし」と表示します
- 両方が SELECT のときは **確認用の SQL** を表示します。2 本の SQL の結果を `EXCEPT ALL` で両方の向きに突き合わせる SQL で、コピーして自分の DB で実行します（このアプリは SQL をどこにも送りません）。両方とも 0 行なら、実行したときのデータでは同じ行が同じ数だけ返っています。並び順は比べません。値は列の照合順序で比べるので、大文字と小文字を区別しない照合順序では 'abc' と 'ABC' のような値を同じとみなすことがあります。MySQL 8.0.31 以降で実行できます

#### 合接クエリ範囲での等価証明

一般の SQL 意味等価は決定不能ですが、**合接クエリ（conjunctive query）** に収まる範囲なら等価性を厳密に判定できます（Chandra-Merlin の準同型定理）。この範囲に限って、構文が違っても「結果セットは同じ」と言い切ります。

判定対象になる条件（すべて満たすときのみ）:

- INNER / CROSS / STRAIGHT_JOIN と暗黙結合のみ（OUTER・NATURAL は対象外）
- 条件は `AND` と `=` のみ。オペランドは修飾済みの列参照か数値 / 文字列リテラル（`b'101'`、`0x41`、`_binary'x'`、`DATE '2024-01-01'` のような、接頭辞の付くリテラルは対象外）
- 正の相関 `EXISTS`（半結合）は本体に展開して扱う。`NOT EXISTS` は対象外
- 出力列は修飾済みの単純な列参照のみ（`*`・関数・式は対象外）
- GROUP BY / HAVING / LIMIT / OFFSET / UNION / CTE / 派生テーブルがない
- テーブル参照が 8 個以内、条件（等式）と出力列がそれぞれ 32 個以内（探索に時間がかかり、比較のたびに画面が止まるのを防ぐため）

これにより「相関 EXISTS ↔ INNER JOIN + DISTINCT」「WHERE ↔ ON の移動」「同じ等式を持つ冗長な結合」などが、パターンマッチではなく同一の正規形として一致します。

`=` は、書かれた等式そのものを比べます。等式から別の等式を導く推移律や、`a.id = a.id` を常に真とみなす反射律は使いません。MySQL の `=` は、型の違う値の比較（`'1.0' = 1` と `1 = '1'` は真、`'1.0' = '1'` は偽）や NULL で、これらの性質を満たさないためです。テーブル名の大文字小文字も区別します（Linux の MySQL では `Users` と `users` は別のテーブルです）。

安全側の設計:

- **許可リスト方式** — 対象外の構文が 1 つでもあれば即座に判定を諦め、従来の構文差分表示に戻ります
- **字句レベルの二重チェック** — 構文木とは別に元 SQL を走査し、対象外のキーワード・演算子があれば拒否します
- **探索予算** — 上限を超えたら「証明できなかった」扱いにします（打ち切りで「同じ」とは言いません）
- **DISTINCT の非対称** — 片方だけ `DISTINCT` の場合は緑にせず「重複を除けば同じ」と表示します（元テーブルに重複行があると行数が変わるため）

### その他

- **別名を実テーブル名で表示** — タブの並びの右端のチェックで、JOIN 図・条件・SQL構造の表示名を切り替え（単一解析）
  - 自己結合の別名（`u1` / `u2`）は切り替えても残します。同じ `users` に潰すと「users の行をすべて残し users を LEFT JOIN」のように説明が読めなくなるためです。実テーブル名はテーブルのラベルに併記されます
  - チェックを外したままでも、SQL構造・作用説明の別名（点線の下線付き）にマウスを載せると、実テーブル名が表示されます
- **SQL と表示の連動** — 右側の要素をクリックすると、左の SQL の該当箇所が強調表示されます。逆に、左のエディタでカーソルを置いた語に対応する要素が、右側で枠に囲まれます（SQL構造・JOIN 図・サブクエリ）
- **リンクをコピー** — 入力中の SQL を URL の `#` 以降に入れたリンクをコピーします。`#` 以降は HTTP リクエストに含まれないので、公開サイトで使ってもサーバーに SQL は送られません。リンクを開くとその SQL を読み込みます。読み込んだ SQL は編集するまで保存しないので、保存していた自分の SQL は残ります
  - `file://` で開いた配布物のリンクは、受け取った人も同じ場所に配布物を置いていないと開けません
  - リンクの一部が欠けているなどで読み込めないときは、ヘッダーにそのことを表示し、それまでの SQL をそのまま残します
- **配色** — ヘッダーで自動（OS の設定に従う）・ライト・ダークを選べます。選んだ値はブラウザに保存します

## オフライン配布

`npm run build` の成果物は **`dist/`** に出力されます。

```
dist/
  index.html      … CSS は <style> にインライン、JS は ./assets/app.js を参照
  assets/app.js
  assets/app.css  … ビルド生成物（index.html からは参照しない）
```

**インライン CSS + classic script（非 module）** のため、`dist/index.html` をブラウザで直接開いても利用できます（`dist/assets/app.js` も同じフォルダに必要）。

> `file://` では外部 CSS（`<link href="...">`）と ES module の外部読み込みが CORS でブロックされます。CSS は HTML 内に埋め込み、JS は IIFE の classic script で読み込みます。

リポジトリには `dist/` も同梱しているため、Node.js がなくても配布物だけでオフライン利用できます。

配布物を更新する場合:

```bash
npm run build              # オフライン配布向け
npm run verify-dist-offline # file:// 直開き向けか検証
npm run ensure-dist        # push 前: 再ビルド + 検証 + dist 同期チェック
```

## 対応範囲

### 文種

- **SELECT**（UNION / サブクエリ / 派生テーブル含む）
- **UPDATE**（JOIN 付き、SET 句。列を既定値に戻す `SET a = DEFAULT` も読む。複数のテーブルを使う UPDATE の ORDER BY と LIMIT は、MySQL と同じくエラーにする）
- **DELETE**（複数テーブル指定。`DELETE t1 FROM …` と `DELETE FROM t1 USING …` のどちらの書き方も読む。削除するテーブルを書かない `DELETE FROM t1 JOIN t2 …` と、複数のテーブルを使う DELETE の ORDER BY と LIMIT は、MySQL と同じくエラーにする）

### SQL 構文（主要）

- JOIN: INNER / LEFT / RIGHT / FULL / CROSS / **STRAIGHT_JOIN**、**NATURAL JOIN**、**JOIN USING**、暗黙 JOIN（カンマ区切り）。ON の無い結合は、すべての行の組み合わせ（直積）として説明します
- 日本語などの ASCII 以外の文字を使った識別子（引用符なしの `FROM 注文` も読む）
- `FROM DUAL`（FROM の無い SELECT と同じに扱う）
- **WITH（CTE）** — 定義の解析と FROM 参照の紐付け、作用説明での表示
- WHERE / HAVING: 比較、IN、BETWEEN、LIKE、IS NULL、EXISTS、NOT、AND / OR
- GROUP BY / ORDER BY / LIMIT / OFFSET / DISTINCT
- 集約関数の DISTINCT（`COUNT(DISTINCT x)`、`SUM(DISTINCT x)`、`AVG` / `MIN` / `MAX` も同じ）
- MySQL ヒント・修飾子: `SELECT STRAIGHT_JOIN`（クエリ単位の結合順ヒント。FROM の JOIN 種別は書き換えない） / `DISTINCTROW` 等、`USE`/`FORCE`/`IGNORE INDEX`、`PARTITION`、`UPDATE`/`DELETE` の `LOW_PRIORITY` / `IGNORE` / `QUICK`

### 未対応・制限

- INSERT / REPLACE など上記以外の文種
- 複数文（`;` 区切りで 2 文以上）— 1 文目だけ解析して残りを黙って捨てないよう、エラーにします
- 括弧でまとめた JOIN（`a LEFT JOIN (b JOIN c ON …) ON …`）— 括弧の中のテーブルを図に出せないため、エラーにします
- UNION の右側だけを括弧で囲む書き方（`SELECT … UNION (SELECT …)`）— SQL パーサが右側のブランチを読み飛ばすため、エラーにします。両側を括弧で囲むか、括弧を外すと解析できます
- 括弧の中で集合演算をまとめる書き方（`(SELECT … UNION SELECT …) EXCEPT SELECT …`）— SQL パーサが読めないため、エラーにします
- NULL 安全な等価演算子 `<=>` — SQL パーサーが読めないため、エラーにします
- 中身が SQL として実行されるコメント `/*! … */`（`/*!80000 … */` のようにバージョンを付けた形も）— SQL パーサーが普通のコメントとして読み飛ばし、中に書いた条件が無い文として解析してしまうため、エラーにします
- `||`（OR）と `XOR` を括弧なしで比較と並べる書き方（`a = 1 || b = 2`）— SQL パーサーが比較より先に結び付けて MySQL と違う意味になるため、エラーにします。`(a = 1) OR (b = 2)` のように括弧で囲むと解析できます
- SQL パーサーが読めない一部の書き方（`SUBSTRING(a FROM 2 FOR 3)`、`.5` のように 0 を省いた小数、WHERE の中の `BINARY a`、`SOUNDS LIKE` など）— 構文エラーとして位置を示します
- ウィンドウ関数の専用説明
- オプティマイザヒントコメント（`/*+ STRAIGHT_JOIN */` 等）
- 実行計画・実際の行数取得（解析・可視化のみ）
- SQL前後比較における一般の意味的等価の証明（合接クエリ範囲を超えると構文差分の検出まで）
